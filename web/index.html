The problem / 问题

AI agents are starting to act on our behalf — reading data, calling tools, spending money — but a resource owner has no standard way to ask, before granting access: Who is this agent? Who vouches for what it can do? Did I actually delegate this to it — and can I take that back?

1 · Identity 身份

A DID the agent authenticated with — did:t3n:… on the live T3N backend.

2 · Attestation 能力证明

A capability claim issued by a trusted third party. Revocable and expirable.

3 · Delegation 限域授权

A scoped grant from the resource owner: one resource, named functions only, revocable at any time.

Every registration, grant, revocation and gate decision is written to an audit trail （全程审计留痕）. Revoking either the attestation or the delegation immediately closes the gate — try it below.

The story / 演示路线

Same story as src/demo.ts (npm run demo): an org registers a research agent, an auditor attests its data.read capability, and the data owner delegates records.read on one vault. Then watch the gate close — twice, for two different reasons.

  1. Register the agent → issue attestation → grant delegation （注册 → 发证明 → 给授权）
  2. Verify access → ALLOWED — all three layers valid （三层齐备，放行）
  3. Revoke the delegation → verify again → DENIED · delegation_revoked （撤授权，立即被拒）
  4. Grant a fresh delegation, revoke the attestation → verify → DENIED · attestation_revoked （撤证明，同样立即被拒）

How the gate decides / 判定规则

verifyAccess checks fail-closed in this order — identity → attestation → delegation; within a layer, revoked is reported before expired. An expiresAt in the past — or exactly equal to now — counts as expired; no expiresAt means valid until revoked. Per layer, the first matching record is the one evaluated (behaviour pinned by the M1 test suite; see M1-REPORT.md).

Reason codeMeaning
unknown_agentNo passport registered for the agent DID
missing_attestationNo attestation for the capability from a trusted issuer
attestation_revokedThe attestation was revoked by its issuer
attestation_expiredThe attestation's expiresAt has passed
missing_delegationNo grant covers this action on this resource
delegation_revokedThe grant was revoked by the resource owner
delegation_expiredThe grant's expiresAt has passed

What changes in M2 — live T3N testnet / M2 里程碑：接真实测试网

This page runs a browser port of PassportService on an in-memory backend — the identical logic to src/passport.ts / src/backend.ts, and the same story the 27-test suite in test/passport.test.ts pins down. The service talks only to the PassportBackend interface, so M2 swaps only the backend: InMemoryBackend is replaced by T3nBackend (src/t3n/adapter.ts, @terminal3/t3n-sdk 5.31.0), and this page then reads live testnet state instead of the in-browser store. The gate logic, the check order and the reason codes do not change.
